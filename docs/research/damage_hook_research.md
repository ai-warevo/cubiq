# Исследование функции урона (AssaultCube 1.3.0.2)
**Цель:** Создание ассемблерного скрипта на God Mode (Бессмертие) и One Hit Kill (Убийство с одного выстрела).

---

## 1. Итоговый рабочий скрипт (Cheat Engine Auto Assembler)

Этот скрипт внедряется в общую функцию распределения урона игры, проверяет адрес цели с помощью одной инструкции `cmp` и изолирует локального игрока от ботов.

```assembly
[ENABLE]
define(INJECT, ac_client.exe+1C223)

assert(INJECT, 29 73 04 8B C6)
registersymbol(INJECT)

alloc(newmem, 2048)
label(returnhere)
label(originalcode)

newmem:
  // Read our player's current intermediate address in a single step (0xEC - 0x04 = 0xE8)
  lea eax, [[ac_client.exe+17E0A8]+0E8]

  // Compare the damage target with our aligned address
  cmp ebx, eax
  je originalcode

  // Instant kill for enemies
  mov [ebx+04], 0

originalcode:
  // Restore the overwritten instruction
  mov eax, esi         
  jmp returnhere

INJECT:
  jmp newmem
returnhere:

[DISABLE]
define(INJECT, ac_client.exe+1C223)
unregistersymbol(INJECT)
dealloc(newmem)

INJECT:
  sub [ebx+04], esi
  mov eax, esi
```

## 2. Пошаговый процесс исследования в Cheat Engine

### Этап 1: Поиск адреса здоровья игрока (Health Pointer)
1. Запустили AssaultCube, зашли в матч с ботами. Здоровье равно `100`.
2. В Cheat Engine нажали **Select a mouse to attach to a process** (иконка монитора сверху слева) -> выбрали процесс `ac_client.exe`.
3. В поле **Value** ввели `100`, тип данных **Value Type** — `4 Bytes`. Нажали **First Scan**.
4. В игре получили урон (прыжок с высоты), ХП упало до `82`.
5. В Cheat Engine ввели `82`, нажали **Next Scan**. Повторили до тех пор, пока не остался один динамический адрес здоровья.
6. Переместили его в нижнюю таблицу по двойному клику.

### Этап 2: Поиск статического указателя структуры игрока
1. Нажали правой кнопкой мыши по найденному адресу здоровья в нижней таблице -> **Find out what writes to this address** (или горячая клавиша `F6`). Появилось окно отладчика.
2. В матче получили урон. В окне отладчика зафиксировали ассемблерную инструкцию перезаписи.
3. Кликнули по инструкции, в нижней панели отладчика прочитали: *“The database register pointer to read this address is probably XXXXXXXX”*.
4. Скопировали этот адрес начала структуры игрока, провели поиск по нему через галочку **Hex** в главном окне.
5. Нашли статический «зеленый» указатель: **`ac_client.exe + 0x0017E0A8`**.
6. При проверке через добавление адреса вручную (**Add Address Manually** -> флажок **Pointer**) убедились, что `ac_client.exe + 0x0017E0A8` со смещением **`0xEC`** стабильно показывает текущее ХП.

### Этап 3: Анализ функции распределения урона
1. Находясь в окне отладчика (`F6`) на адресе здоровья, обратили внимание на точную инструкцию уменьшения ХП:
   ```text
   0041C223 - 29 73 04 - sub [ebx+04], esi
   ```
   *Вывод:* Внутри функции урона игра использует промежуточный адрес в регистре `ebx`. Точка отсчета смещена: здоровье находится по смещению `0x04`, а не `0xEC`.
2. Выделили эту строку кликом мыши и нажали кнопку **Show disassembler** на панели отладчика справа. Открылось окно **Memory Viewer**.
3. Проанализировали байты, идущие сразу за инструкцией урона:
   ```text
   0041C223 - 29 73 04 - sub [ebx+04], esi
   0041C226 - 8B C6    - mov eax, esi
   ```
   *Критическое замечание:* Инструкция инъекции `jmp newmem` в 32-битных приложениях всегда весит **5 байт**. Сама команда `sub` занимает всего **3 байта** (`29 73 04`). Чтобы встроить прыжок, Cheat Engine затирает следующие **2 байта** (`8B C6` — команда `mov eax, esi`). Их необходимо вручную восстановить в блоке `originalcode`.

### Этап 4: Разделение адресов (Логика фильтрации)
Попытка напрямую сравнить `ebx` (цель урона) и статический адрес начала игрока `ac_client.exe+17E0A8` приводила к тому, что все существа (включая игрока) умирали с одного удара. 

*Причина:* Разные точки отсчета адресов. `ebx` хранит промежуточный адрес, сдвинутый ближе к переменным. 
*Математический расчет сдвига:* `0xEC` (реальное смещение ХП) - `0x04` (смещение ХП в функции) = **`0xE8`**.

*Решение:* Использование оптимизированной инструкции **`lea`** (Load Effective Address). Команда `lea eax, [[ac_client.exe+17E0A8]+0E8]` вычисляет точный сдвинутый адрес нашего игрока как число за один такт процессора.
* Если `ebx` равен `eax` (стреляют в нас) — код прыгает по метке `je originalcode`, где строка вычитания здоровья `sub` закомментирована (**God Mode**).
* Если `ebx` не равен `eax` (стреляют во врага) — принудительно выставляется `mov [ebx+04], 0` (**One Hit Kill**).
