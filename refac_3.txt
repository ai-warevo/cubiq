# TASK 3: Namespace Refactoring - Platform & Games Layer

You are a senior developer continuing a multi-stage namespace refactoring process. This task focuses on the platform abstraction and game-specific implementations.

## Prerequisites
This task assumes that **TASK 1** and **TASK 2** have been completed. The `cubiq::common` prefix is now correctly used for all core components.

## Mapping Rules
1. The base namespace is `cubiq`.
2. Files in `platform/<platform_name>/` MUST use `cubiq::platform::<platform_name>` as their prefix (e.g., `platform/base/inc/IMemoryAccess.hpp` -> `cubiq::platform::base`).
3. Files in `games/<game_name>/` MUST use `cubiq::<game_name>` as their prefix (e.g., `games/assaultcube/external/inc/ACPlayer.hpp` -> `cubiq::assaultcube::external`).
4. Skip `inc` and `src` directories when constructing the namespace path.

## Target Files for this Task

### 1. Platform (`platform/`)
- Expected prefix: `cubiq::platform::<subfolder>`
- Files (examples):
  - `platform/base/inc/IMemoryAccess.hpp` -> `cubiq::platform::base`
  - `platform/base/inc/IInput.hpp` -> `cubiq::platform::base`
  - `platform/win32/inc/Win32Memory.hpp` -> `cubiq::platform::win32`

### 2. Games (`games/assaultcube/`)
- Expected prefix: `cubiq::assaultcube::<subfolder>`
- Files (examples):
  - `games/assaultcube/external/inc/ACPlayer.hpp` -> `cubiq::assaultcube::external`
  - `games/assaultcube/external/inc/HealthModulator.hpp` -> `cubiq::assaultcube::external`
  - `games/assaultcube/structures/inc/Offsets.hpp` -> `cubiq::assaultcube::structures` (Note: currently uses `cubiq::assaultcube::offsets`, change to `structures`)

## Instructions
1. Update the namespace declarations in the target files.
2. Ensure that all `#include` statements within these files are updated to point to the correct namespaces for core, platform, and game components.
3. Report when all target files have been updated.
